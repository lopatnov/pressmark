# Project rules

> **Главная сессия Claude — дирижёр.** Она делает большинство работы сама и вызывает
> специалистов-агентов точечно, для конкретных случаев. Субагенты возвращают результат дирижёру,
> а не друг другу.
>
> Карта процесса:
> - **Когда кого вызывать** → [`workflow.md`](./workflow.md) (базовое правило, примеры, DoD).
> - **Роли** → [`team.md`](./team.md) (8 ролей: кто за что отвечает, политика моделей/инструментов).
> - **Инженерные конвенции** → [`conventions.md`](./conventions.md) (коммиты, версии, ветки, changelog, PR-чеклист).
> - **Должностные инструкции агентов** → [`../agents/*`](../agents/) (шаблон — `_TEMPLATE.md`).
>
> Специфика проекта — в `CLAUDE.md`.

## Ценности проекта

- **Простота.** Стремимся к простому дизайну, простому коду и простым решениям. Сложность — это враг, которого нужно избегать.
- **Надежность.** Стабильная работа важнее новых фич. Предпочитаем проверенные решения и тщательно тестируем изменения. А также приоритет выполнения поставленных задач над новыми задачами. Если есть риск не успеть выполнить задачу, лучше разбить её на более мелкие подзадачи и занести остальные в бэклог, чем рисковать не выполнить задачу. Новые задачи заносятся в бэклог и выполняются по мере возможности, но не должны мешать выполнению уже поставленных задач.
- **Экономность.** Учитываем стоимость ресурсов (время, деньги) при принятии решений. Предпочитаем решения, которые дают наибольшую отдачу при минимальных затратах.
- **Прозрачность.** Открыто обсуждаем проблемы, решения и прогресс. Не боимся признавать ошибки и учиться на них.
- **Гибкость.** Готовы адаптироваться к изменениям и новым требованиям. Не привязываемся к конкретным технологиям или подходам, если они не служат нашим ценностям.
- **Легальность** Соблюдаем законы и этические нормы, особенно в отношении данных и интеллектуальной собственности. Предпочитаем открытые лицензии и уважаем авторские права. Обращаем внимание на лицензии используемых библиотек и моделей, чтобы избежать юридических проблем.

## Дисциплина билдов

- Run [`/build`](../commands/build.md) after every non-trivial change — команда делегирует
  проверку агенту [`build-validator`](../agents/build-validator.md) (он запускает команды из
  `CLAUDE.md`). Команды проверки в `CLAUDE.md` должны быть актуальны.
- A commit is only acceptable when the build is green (0 errors). Warnings should be reviewed.
- Use the [`build-validator`](../agents/build-validator.md) subagent to delegate build/test
  verification — it returns a structured report instead of dumping compiler output into the main context.

## Задачи должны быть декомпозированы

- Так как контекст ограничен на 200K токенов, задачи должны быть разбиты на подзадачи, которые можно выполнить в рамках этого ограничения. Это позволяет избежать потери контекста и обеспечивает более эффективное выполнение задач.
- Если возможно разбить проект на модули, библиотеки, фичи или компоненты, это следует сделать, чтобы обеспечить более четкую структуру и облегчить управление зависимостями.

## Экономия средств и предотвращение гонок

- git push выполнять не больше одного раза в час, чтобы не спамить CI и не создавать гонки между PR, но можно делать больше если попросит пользователь.

## Ревью PR

- Если один из CI не выполняется, значит для начала нужно посмотреть историю выполнения CI, чтобы понять на каком комите начались проблемы
