# Team — роли, субординация, RACI

> Веб-нейтральный файл. Описывает **кто за что отвечает** и **к кому обращаться**.
> Процесс по фазам — в `workflow.md`. Должностные инструкции — в `.claude/agents/*`.

## Лин-ядро и опциональные роли

**Лин-ядро** (активные, вызываются регулярно):
`business-analyst`, `architect`, `scrum-master`, `manager`, `server-developer`, `ui-developer`,
`designer`, `tester`, `manual-tester`, `security-engineer`, `technical-writer`, `devops`,
`build-validator`.

**Опциональные** (реальные роли-стабы; наполняй по `_TEMPLATE.md` при необходимости):
`qa` (дешёвый ресёрч-помощник), `release-engineer`, `lawyer`, `translator`.

**Консолидированные роли** (отдельных файлов нет — поглощены core-агентом; если проект перерастёт
ядро, создай отдельный файл из `_TEMPLATE.md`):
- UI-дизайн, UX-дизайн, креативное направление → `designer`
- DevSecOps (безопасность в CI/CD) → `security-engineer` + `devops`
- Full-stack-интеграция → роль дирижёра (главная сессия) + `architect`; отдельный агент не нужен

## Субординация и эскалация

- **В своей зоне роль — главная** («главный в своих вопросах»). Дирижёр уважает решение роли,
  но отвечает за переход между воротами и за общий бюджет.
- **Архитектурный конфликт** (сложность, связность, выбор технологии) → `architect`. Его слово
  решающее в вопросах структуры. Tester при чрезмерной сложности метода идёт к `architect`.
- **Конфликт объёма/приоритета** → `scrum-master` (что в спринте, что в backlog). Приоритет —
  закончить начатое.
- **Неясность требований** → `business-analyst` → при необходимости вопрос пользователю.
- **Риск безопасности/легальности** → `security-engineer` / `lawyer`; могут заблокировать ворота
  Quality/Release до устранения.
- **Состояние самой команды** (агенты, правила, доки, бюджет сессии) → `manager`.
- Если роли не хватает ресурса/информации для задачи — это **не повод бросить задачу**: дефицит
  оформляется в backlog (`scrum-master`), а не теряется.

## Политика моделей (экономность)

| Модель | Роли | Почему |
|--------|------|--------|
| **opus** | `architect` | глубокое рассуждение, цена ошибки в архитектуре высока |
| **sonnet** | BA, scrum-master, manager, разработчики, designer, tester, manual-tester, security-engineer, technical-writer, devops, release-engineer | основной рабочий объём |
| **haiku** | `build-validator`, `translator`, `qa`, `lawyer` | рутина/дёшево; можно поднять при необходимости |

При появлении объёмной рутины — создать дешёвого (haiku) под-агента, чтобы не нагружать дорогую модель.

## Политика инструментов (`tools:`)

Реальные имена Claude Code (не выдуманные): `Bash, Read, Glob, Grep, Edit, Write, Task,
TodoWrite, WebFetch, WebSearch`.

- **Стандартный набор** (большинство ролей): все перечисленные.
- **`build-validator`**: только `Bash, Read, Glob, Grep` — read-only + запуск проверок, без записи.
- **`manual-tester`**: `tools` **не указан намеренно** → наследует все инструменты, включая
  браузерные MCP (`mcp__chrome-devtools__*`, `mcp__Claude_Preview__*`), состав которых зависит
  от проекта.

> Имя файла агента **обязано** совпадать с полем `name:` во frontmatter.
