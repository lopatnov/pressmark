# Внутренняя документация для Claude

Это внутренняя память дирижёра (не документация продукта — та в README/CHANGELOG, зона
`technical-writer`). Обновляется дирижёром напрямую по мере необходимости, отдельной роли для
этого нет.

## Порядок чтения при старте сессии
`CLAUDE.md` → `rules/index.md` → `rules/workflow.md` → `rules/team.md`. Дальше — профильные
файлы агентов по мере вызова ролей.

## Почему 8 ролей, а не «лин-ядро» из 13+

Изначальный шаблон принёс 18 ролей, скопированных под общий случай (business-analyst, designer,
lawyer, manager, scrum-master, translator, manual-tester, qa, release-engineer и т.д.). Для
проекта, который уже построен и нуждается в поддержке одной сессией (плюс точечные субагенты),
это оказалось избыточным процессом, не соответствующим реальной нагрузке — большинство ролей ни
разу не вызывались. Роли оставлены только там, где регулярно нужна (а) отдельная экспертиза
(архитектура, безопасность), (б) изоляция шумного вывода (`build-validator`), или (в) достаточно
крупная автономная подзадача. У каждого агента — свой чистый контекст, поэтому дробить роли
дальше есть смысл только когда одной из восьми зон реально не хватает объёмно и регулярно, а не
заранее «на будущее».
